# NiTruX — audit complet (2026-09-21)

Version auditée : `0.25.149` (dernière release publiée : `v0.25.148`).
Référence de parité : Nitrite 2.0 (Windows), `D:\Projet\Nitrite 2.0`.

Signalement utilisateur à l'origine de l'audit : « les 3/4 des fonctionnalités ne
fonctionnent pas, il manque beaucoup trop de choses par rapport à Nitrite Windows,
et l'AppImage est encore pire que les autres formats ».

---

## 1. Cause racine du « 3/4 ne fonctionne pas »

Ce n'est **pas** un défaut de câblage ni du code mort. Les vérifications suivantes
sont toutes ressorties propres :

| Vérification | Résultat |
|---|---|
| `invoke()` frontend ↔ `generate_handler!` backend | 83 = 83, zéro orphelin dans les deux sens |
| Boutons sans action, handlers vides, badges « bientôt disponible » | 0 |
| `todo!()` / `unimplemented!()` / données factices | 0 |
| Cohérence pkexec (tauri.conf.json ↔ `PKEXEC_BINARY_NAMES` ↔ 5 `.policy` ↔ helper) | 15 = 15 = 15 = 15, aucune divergence |

La cause réelle est **l'environnement d'exécution**, et elle se décompose en trois
défauts bien identifiés :

### 1.1 NiTruX dépend de ~20 outils externes, n'en déclare aucun, et ne dit pas lesquels manquent

`src-tauri/tauri.conf.json` ne contient **aucune clé `depends`** ni pour le `.deb`,
ni pour le `.rpm`. Installer NiTruX n'installe et ne recommande donc rien.

Outils réellement absents d'une installation standard (vérifié sur Ubuntu 22.04
minimale) : `smartctl`, `sensors`, `traceroute`, `dig`, `timeshift`, `clamscan`,
`nvme`, `efibootmgr`, `flatpak`, `docker`, `bluetoothctl`, `nmcli`, `lpstat`,
`pactl`, `xrandr`, `lsusb`, `crontab`.

Chaque outil absent désactive une page ou une section entière. Vingt outils
absents sur une machine fraîche, c'est exactement l'impression « les trois quarts
de l'application ne marchent pas ».

### 1.2 Cinq commandes échouaient en silence, sans qu'aucun message ne soit possible

| Commande | Signature avant | Conséquence |
|---|---|---|
| `get_monitors` (`xrandr`) | `Vec<String>` | liste vide, `try/catch` frontend jamais déclenché |
| `get_usb_devices` (`lsusb`) | `Vec<String>` | idem |
| `get_audio_sinks` (`pactl`) | `Vec<AudioSink>` | idem |
| `get_printers` (`lpstat`) | `Vec<PrinterInfo>` | idem |
| `get_bluetooth_status` (`bluetoothctl`) | struct sans champ d'erreur | « aucun adaptateur Bluetooth » alors que c'est `bluez` qui manque |

Une commande Tauri qui ne renvoie pas `Result` ne peut **jamais** rejeter côté JS :
les blocs `try/catch` de `PeripheralsPage.vue` étaient du code mort pour le cas qui
se produit réellement sur le terrain. « Outil non installé » et « ce matériel
n'existe pas » rendaient exactement pareil : une liste vide.

Même schéma dans `drivers.rs` : le hint `(paquet requis : pciutils)` était bien
construit, puis jeté par un `.unwrap_or_default()` en aval — le tableau des
périphériques restait vide sans explication.

### 1.3 Quand un message existait, il ne nommait pas le paquet

`dig introuvable ou impossible à lancer : No such file or directory` est exact et
inutilisable : le nom du paquet ne se déduit pas du nom du binaire
(`dig` → `dnsutils`, `lspci` → `pciutils`, `xrandr` → `x11-xserver-utils`).
Seuls 3 modules sur ~30 nommaient le paquet (`smart.rs`, `malwarescan.rs`,
`docker.rs`), chacun avec son propre code ad hoc.

### 1.4 Pourquoi l'AppImage est pire

Deux défauts propres à ce format, tous deux corrigés en v0.25.145 mais qui
expliquent l'historique : fuite de `LD_LIBRARY_PATH` dans tous les sous-processus
(crash de `curl` et de tout binaire système partageant une lib avec le bundle), et
montage FUSE illisible par root qui empêchait l'installation des 15 binaires
pkexec — donc **toutes** les actions administrateur échouaient en cascade.
Reste vrai aujourd'hui : l'AppImage doit installer son intégration pkexec au
premier lancement, alors que `.deb`/`.rpm` la reçoivent du gestionnaire de paquets.

### Fonctionnalités ajoutées dans la foulée

| Fonctionnalité | Détail |
|---|---|
| Actions Docker | Démarrer / arrêter / redémarrer un conteneur, afficher ses 200 dernières lignes de journal, supprimer une image — non privilégié (groupe `docker`), identifiants validés en hexadécimal strict et actions en liste blanche |
| Bluetooth : activer / désactiver | `bluetoothctl power on\|off`, sans nouvelle élévation |
| Liste des sauvegardes | `list_backups` : archives `nitrux-backup-*.tar.gz` du dossier personnel, taille et date, triées de la plus récente à la plus ancienne |
| Vider le cache DNS | Bouton sur la page DNS Switcher (`resolvectl flush-caches`) |
| Benchmark multicœur | Le benchmark CPU ne mesurait qu'un seul cœur : ajout du même test lancé sur tous les cœurs, avec le nombre de cœurs utilisés |
| Imprimante par défaut | `lpoptions -d`, non privilégié (préférence utilisateur dans `~/.cups/lpoptions`) |
| `/etc/hosts` ligne par ligne | Activer / désactiver / supprimer / ajouter une entrée, avec validation IP et nom d'hôte. Transformations de texte pures côté client, écriture par le chemin privilégié existant — aucune nouvelle surface pkexec. L'édition brute du fichier reste disponible |

Décision prise et assumée : **ne pas** ajouter de `depends` dur aux paquets
`.deb`/`.rpm`. Les noms divergent entre distributions et versions
(`policykit-1` n'existe plus sous Debian 12, devenu `polkitd`) : un nom erroné
casse l'installation entière. La détection à l'exécution + l'installation en un
clic couvre le besoin sans ce risque.

## 3. Parité Nitrite Windows → NiTruX

Chiffres bruts : **346 commandes backend** côté Windows, **84** côté Linux
(291 vs 83 réellement appelées par le frontend). L'écart réel est inférieur à ce
que ces nombres suggèrent — Windows éclate en 3 commandes ce que Linux fait en une
(`winget`/`chocolatey`/`scoop` → `detect_native_manager`) — mais il reste large.

Deux manques signalés par l'audit de parité ont été vérifiés et écartés : les
ports en écoute (`ss -tulnp`) et le scan des réseaux Wi-Fi (`nmcli`) existent déjà,
agrégés dans `get_network_snapshot`.

### 3.1 À ajouter — priorité haute (fonctionnalité visiblement manquante)

| Fonctionnalité | Équivalent Linux | Effort |
|---|---|---|
| Import d'une blocklist dans `/etc/hosts` | téléchargement d'une liste puis fusion (l'édition par entrée est faite) | M |
| Benchmark compression / chiffrement | demanderait une dépendance de plus (flate2, aes) pour un chiffre synthétique — décision à prendre | S |
| Historique de performance persistant | actuellement reconstruit en mémoire, perdu à la fermeture | M |
| Visualiseur d'arborescence de disque (façon WinDirStat) | `du` en backend, page `DiskVisualizerPage` à enrichir | M |
| Détail CPU par cœur, cache, température GPU | `lscpu -C`, `sensors`, `nvidia-smi` | M |
| BIOS / carte mère détaillés | `dmidecode -t bios -t baseboard` — exige une nouvelle action pkexec, donc une VM Linux de vérification | S |
| Profils de configuration persistés côté backend (export/import `.json`) | actuellement 100 % côté client (Pinia) | S |

### 3.2 À ajouter — priorité moyenne

Mutations GRUB (timeout, entrée par défaut, `grub-reboot`) · réparation du
chargeur d'amorçage (`grub-install`, `update-grub`) · profils d'alimentation
(`powerprofilesctl`, `tlp`) · redimensionnement de partition dans les deux sens et
création/suppression (`parted`, `sgdisk`) · restauration fichier par fichier dans un
snapshot Timeshift · nettoyage des résidus de configuration orphelins
(`~/.config`, `~/.local/share`) · bibliothèque de scripts intégrés + sauvegarde sur
disque · surveillance en tâche de fond avec notifications (`notify-send`) ·
installation corrective d'une dépendance manquante détectée · audit du démarrage
automatique (`~/.config/autostart`, `systemctl list-unit-files`, crontab) —
c'est l'équivalent conceptuel de l'onglet Registre de Nitrite.

### 3.3 À ajouter — priorité basse

Assistant IA local (llama.cpp/Ollama — le code Rust `ai/*.rs` de Nitrite est
portable presque tel quel) · récupération de fichiers effacés (`testdisk`,
`photorec`, `extundelete`) · image disque (`dd`, `partclone`) · mode Turbo un clic
(décision produit en attente : contredit la philosophie lecture seule de la page
Optimisations) · export de la sélection d'applications.

### 3.4 Hors scope — ne doivent pas exister dans l'app Linux

Page WSL · mode WinPE entier (19 actions) · licences et activation Windows ·
BitLocker · registre Windows · BCD/MBR/DISM/SFC/chkdsk · scanner de DLL ·
LibreHardwareMonitor portable · téléchargement d'ISO Windows ·
winget/chocolatey/scoop en tant que tels.
